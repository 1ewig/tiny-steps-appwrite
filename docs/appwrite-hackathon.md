## 2. The Five Database Types

Pick one as your primary database. Using more is not prohibited, but judging scores "the database you picked."

| Database | Model | Best for | Notes |
| :--- | :--- | :--- | :--- |
| **TablesDB** | Relational: databases → tables → rows; typed columns, relationships, indexes, transactions, realtime, bulk ops | Structured app data (users, tasks, orders, steps) | Shared or dedicated infrastructure; the most flexible default |
| **DocumentsDB** | Document store: databases → collections → documents | Flexible/evolving schemas, quick prototypes | Fastest to model, least differentiated |
| **VectorsDB** | Vector store: collections with a fixed `dimension`, `embeddings` + `metadata`, HNSW index | Semantic search, recommendations, AI recall | Built-in text embedding generation — no separate embedding service needed |
| **Managed PostgreSQL** | Managed Postgres instance | Raw SQL, complex relational queries, migrations | Dedicated infrastructure; check pricing |
| **Managed MySQL** | Managed MySQL instance | Raw SQL on MySQL | Dedicated infrastructure; check pricing |

Docs: [TablesDB](https://appwrite.io/docs/products/databases/tablesdb) · [VectorsDB](https://appwrite.io/docs/products/databases/vectorsdb) · [Databases overview](https://appwrite.io/docs/products/databases) · [Pricing](https://appwrite.io/pricing)

## 3. Rules

1. **Build from scratch.** The project must be entirely new and built during Oct 19–31. Code written before Oct 19 is not eligible. Open-source libraries and frameworks are allowed if listed in the tech stack.
2. **Solo hackers only.** Every project must be designed, built, and submitted by one person.
3. **Build on Appwrite Databases.** The project must use one of the five database types. Projects that don't won't be judged.
4. **Deadline is hard.** Submit by 11:59 PM PT on Oct 31, 2026. Late submissions are not accepted.

The site does not address AI-assistant usage. The rules only require that the project be new and built by one person.

## 4. Judging Criteria

| Criterion | What judges look for |
| :--- | :--- |
| **Idea & innovation** | How original the idea is and the problem it sets out to solve |
| **Technical execution** | How well the project is built, and how well it works |

A polished, focused app can score as well as an ambitious one.

## 6. Submission Requirements

Required:
- **Public code repository** (e.g. GitHub), open source, with a license.
- **Demo video, 2–3 minutes max** (YouTube or similar).
- **Optional live demo link** if deployed.

Flow:
1. Sign in at [hackathon.appwrite.io](https://hackathon.appwrite.io) (Appwrite account; the announcement mentions signing in with GitHub).
2. Open the hacker dashboard.
3. Click **Submit project**.
4. Provide repo URL, video URL, optional live demo URL.
5. Submit before the deadline.

The code must be in a public repo on your account, and the tech stack (including open-source libraries and frameworks used) should be listed in the submission.
